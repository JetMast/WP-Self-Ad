# WP Self Ad · WordPress 自助广告系统

> 一个让访客**自助购买广告位**的 WordPress 插件。站长设好位置和价格，用户自己挑格子、付钱、填内容，到期自动下线。
> 适配子比主题（zibll），也可用于任意 WordPress 站点。

## 它能做什么

传统的 WordPress 广告位靠"贴代码"，卖广告要靠站长手动操作。这个插件把它变成**一套自助交易流程**：

1. **站长**在后台配置广告位（位置、每行容量、月单价、可购买天数）
2. **访客**在前台看到空闲格子（显示"招租"和价格），点一下弹出购买窗口
3. 填写广告内容 → 选投放时长 → 选支付方式 → 付款
4. **支付成功后自动上线**，位置自动占用，不再对外出售
5. 到期后由定时任务**自动下线**，位置释放给下一位

### 核心特性

| 特性 | 说明 |
|---|---|
| 🎯 **自助购买** | 访客点空格子即可下单，无需联系站长 |
| 🎨 **5 种广告位** | 大横幅 / 小横幅 / 迷你横幅 / 方块横幅 / 文字广告，也可自定义 |
| 💰 **按天计价** | 月单价 × 投放天数 ÷ 30，金额**只在服务端计算**，前端改不了 |
| 💳 **多渠道支付** | 支付宝官方、易支付；付款方式支持支付宝 / 微信 / QQ 钱包 |
| 🔀 **多通道自动选路** | 同时配了多个通道时按优先级自动挑（支付宝官方优先，其次易支付） |
| 🔒 **并发安全** | 下单全程事务 + 行锁，同一格子不会被两个人同时买到 |
| ⏰ **自动到期** | 每小时检查一次，过期广告自动下线并释放位置 |
| 🛠️ **站长手动管理** | 后台可自定义广告内容、手动上下架、改投放天数 |
| 📱 **响应式** | 窄屏自动换行、字号自适应，手机上看不会挤变形 |
| 🌐 **零依赖** | 纯 PHP 手写，不需要 Composer / Node，不需要任何第三方库 |

## 安装

### 方式一：后台上传（推荐）

1. 下载最新版 `wp-self-ad-v1.3.7.zip`
2. WordPress 后台 → **插件 → 安装插件 → 上传插件**
3. 选择该 zip 文件 → 点「现在安装」→ 安装完成后点「启用」

### 方式二：手动上传

1. 解压 zip，把 `wp-self-ad` 整个文件夹上传到 `/wp-content/plugins/`
2. 后台 → **插件** → 找到「WP Self Ad - 自助广告系统」→ 点「启用」

### 安装后会自动完成

- 创建 3 张数据表（`wsa_ad_slots` / `wsa_orders` / `wsa_user_ads`）
- 写入 5 种默认广告位
- 注册支付回调地址的伪静态规则，并刷新一次 rewrite

> 如果安装后页面出现 404 或"下单失败"，请到 **设置 → 固定链接** 点一下「保存更改」，
> 强制刷新一次伪静态规则。

## 快速上手

装好后按这 4 步就能跑起来：

### 第 1 步：配置广告位

后台 → **自助广告 → 广告位设置**

每个广告位可以设置这几项：

| 项目 | 说明 |
|---|---|
| 广告位名称 | 比如「首页顶部大横幅」 |
| 每行容量 | 一行排几个格子（决定前台列数） |
| 月单价 | 计价基准，实际金额 = 月单价 × 天数 ÷ 30 |
| 可购买天数 | 下拉给用户选的时长，比如 `7,30,90` |
| 是否启用 | 关掉后前台就不显示这个广告位 |

### 第 2 步：配置支付

后台 → **自助广告 → 支付设置**，至少配通一条支付通道：

- **支付宝官方**：填 AppID、应用私钥、支付宝公钥
- **易支付**：填接口地址、商户 PID、商户密钥，并勾选已开通的付款方式

> 配完建议点一下 **「易支付接口自检」**，插件会用 0.01 元的探测单真实请求一次接口，
> 把服务商的原话抓回来，并给出人话建议。这是排查支付问题最有效的手段。

### 第 3 步：把短代码放到页面上

在任意页面 / 文章 / 小工具里粘贴：

```
[wsa_ad slot="banner_large"]
```

### 第 4 步：前台试买

用任意登录账号点一下空闲格子（显示"招租"的那个），走完下单流程。

## 广告位类型

插件内置 5 种，安装时自动创建：

| 短代码 | 名称 | 类型 | 每行容量 | 桌面高度 | 手机高度 |
|---|---|---|---|---|---|
| `[wsa_ad slot="banner_large"]` | 大横幅广告 | 图片 | 1 | 70px | 70px |
| `[wsa_ad slot="banner_small"]` | 小横幅广告 | 图片 | 2 | 70px | 60px |
| `[wsa_ad slot="banner_mini"]` | 迷你横幅广告 | 图片 | 3 | 50px | 44px |
| `[wsa_ad slot="banner_block"]` | 方块横幅广告 | 图片 | 6 | 80px | 60px |
| `[wsa_ad slot="text_ad"]` | 文字广告位 | 文字 | 4 | 最小 38px | 最小 36px |

**排版规则**：始终「至少留一个空位」，卖满一行就补一整行。
比如每行 4 格的文字广告位，卖出 4 格后会变成 8 格（后 4 格继续招租）。

### 自定义新的广告位

后台可以新建任意广告位，短代码里填你设的 `slot_key` 即可：

```
[wsa_ad slot="我的广告位标识"]
```

## 支付配置

插件采用**两层解耦**的支付模型，理解这两层就能理解全部配置：

### 第一层：付款方式（用户在收银台选的）

| 值 | 名称 |
|---|---|
| `alipay` | 支付宝 |
| `wechat` | 微信支付 |
| `qq` | QQ 钱包 |

### 第二层：支付通道（后台实际对接的接口）

| 通道 | 优先级 | 说明 |
|---|---|---|
| 支付宝官方 | 10（高） | 走支付宝开放平台，需企业资质 |
| 易支付 | 20（低） | 走第三方聚合接口，个人可对接 |

**选路规则**：用户选了某个付款方式后，插件在所有「可用且支持该付款方式」的通道中，
自动挑优先级最小的那个。三处逻辑（收银台显示、后端校验、实际调用）共用同一结果。

### 易支付的两种接口形态

插件支持两种，默认 **自动** 判断：

1. **收银台接口**：`POST {接口地址}/mapi.php` → 返回 `{code, msg, payurl}` → 跳转 `payurl`（新式平台，推荐）
2. **页面跳转**：`GET {接口地址}/submit.php?参数`，直接把浏览器送过去（老式易支付）

自动模式下，如果 `mapi.php` 返回的不是 JSON，会**自动回退**到第 2 种。

> 跳转前插件会做一次**收银台预检**：部分平台配置有误时 `payurl` 返回的是 JSON 报错而不是网页。
> 预检仅在响应体是 JSON 时拦截，并把服务商的原话弹给用户；正常网页一律放行。

### 接口地址怎么填

只需要填**域名**即可，插件会自动推导出 `mapi.php` / `submit.php`：

```
https://你的易支付域名.com
```

也兼容直接填完整地址（如 `https://xxx.com/mapi.php`）。

### 扩展新的支付通道

插件提供了两个过滤器，可以在不改动插件源码的情况下接入新通道：

```php
// 增加付款方式
add_filter( 'wsa_payment_types', function ( $types ) {
    $types['my_pay'] = '我的支付';
    return $types;
} );

// 增加支付通道
add_filter( 'wsa_payment_channels', function ( $channels ) {
    $channels['my_channel'] = [
        'label'    => '我的通道',
        'priority' => 30,
        'handler'  => 'my_channel',
        'check'    => 'my_channel_is_configured',
        'types'    => [ 'my_pay' => 'my_type_code' ],
    ];
    return $channels;
} );
```

## 后台功能

安装后左侧菜单会多出 **「自助广告」** 一级菜单，包含 6 个页面：

| 页面 | 作用 |
|---|---|
| **仪表盘** | 收入 / 订单 / 广告位概况，以及上次数据库错误（如有） |
| **广告位设置** | 配置每个广告位的名称、容量、价格、天数、启用状态 |
| **广告管理** | 查看全部广告，可**手动添加**、编辑内容、上架 / 下架、删除 |
| **订单管理** | 查看订单列表与状态（待支付 / 已支付 / 已过期 / 已关闭 / 待核对） |
| **支付设置** | 配置支付宝官方与易支付；提供**接口自检**与**数据库修复**工具 |
| **关于插件** | 插件信息与作者联系方式 |

### 广告管理的一些细节

- **站长广告与用户广告共用一张表**，用 `source` 字段区分（`admin` / `user`）
- 广告状态只有三种：`active`（在线）/ `paused`（站长下架）/ `expired`（到期）
- **下架即释放格子**，不会影响已支付的订单
- 站长**可以**改站长的广告天数；用户购买的广告**只能改内容**，位置和天数不能动（否则与订单对不上）
- 对已过期的广告点「上架」，会按投放天数**自动续期**，不会出现"上架了却马上消失"

## 数据表

插件会创建 3 张表（`{prefix}` 是你的 WordPress 表前缀）：

### `{prefix}wsa_ad_slots` — 广告位定义

| 字段 | 说明 |
|---|---|
| `slot_key` | 广告位标识，短代码里填的就是它 |
| `slot_name` | 显示名称 |
| `slot_type` | `image` 或 `text` |
| `max_items` | 每行容量 |
| `price` | 月单价 |
| `duration_options` | 可选天数（存为 JSON 数组） |
| `is_enabled` | 是否启用 |

### `{prefix}wsa_orders` — 订单

| 字段 | 说明 |
|---|---|
| `order_no` | 订单号 |
| `user_id` / `slot_id` / `slot_position` | 买家、广告位、位置序号 |
| `duration` | 投放天数 |
| `amount` | 实际金额（服务端计算） |
| `payment_method` | 用户选的付款方式 |
| `payment_channel` | 实际使用的支付通道 |
| `status` | `pending` → `paid` → `expired`；另有 `closed` / `review` |
| `image_url` / `text_content` / `link_url` | 广告内容 |

### `{prefix}wsa_user_ads` — 广告（用户购买的 + 站长添加的）

| 字段 | 说明 |
|---|---|
| `source` | `user` 或 `admin` |
| `slot_position` | 占用的位置序号 |
| `status` | `active` / `paused` / `expired` |
| `duration` | 投放天数（供续期） |
| `expires_at` | 到期时间（`2099-12-31 23:59:59` 表示永久） |
| `admin_note` | 站长备注（不对外） |

> ⚠️ **卸载插件会永久删除全部数据！**
> 在 WordPress 后台「卸载」本插件时，`uninstall.php` 会执行
> `DROP TABLE` 删掉上面 3 张表，并清除 `wsa_alipay_config` / `wsa_epay_config` 等配置项
>（多站点环境下会对每个子站点各执行一次）。
>
> **只是停用（Deactivate）不会删数据** —— 停用是安全的，可以随时重新启用。
> 如果只是想暂时不用，请务必选择「停用」而不是「卸载」。
> 卸载前请先备份数据库。

## 目录结构

```
wp-self-ad/
├── wp-self-ad.php              # 插件入口：常量、自动加载、激活/停用钩子、资源加载
├── uninstall.php               # 卸载时的清理逻辑
├── admin/
│   └── class-wsa-admin.php     # 后台全部页面与表单处理
├── includes/
│   ├── class-wsa-db.php        # 数据层：表结构定义、建表、补字段、数据迁移
│   ├── class-wsa-ad-slots.php  # 广告位：容量计算、短代码渲染
│   ├── class-wsa-ad-manager.php# 广告的唯一读写入口（查询/保存/上下架/删除）
│   ├── class-wsa-orders.php    # 订单：创建、支付回调、事务与幂等
│   ├── class-wsa-payment.php   # 支付：付款方式与通道注册、选路、签名、回调
│   ├── class-wsa-ajax.php      # 前端接口（admin-ajax）
│   ├── class-wsa-cron.php      # 定时任务：每小时检查过期广告
│   └── class-wsa-about.php     # 后台版权信息展示
└── assets/
    ├── css/wsa-frontend.css    # 前台样式（含响应式）
    ├── js/wsa-frontend.js      # 前台交互（购买弹窗）
    └── js/wsa-admin.js         # 后台交互
```

### 代码组织约定

- **纯 PHP 手写**，无 Composer、无命名空间
- 类名统一 `WSA_` 前缀 + 全大写下划线风格，如 `WSA_Ad_Manager`
- **自定义自动加载器**：`WSA_Xxx_Yyy` → `includes/class-wsa-xxx-yyy.php`
- 数据访问集中在 `WSA_DB`，**表结构的唯一权威来源是 `WSA_DB::schema()`**
- 时间统一使用 `WSA_DB::now()`（站点时区），**禁止**在 SQL 里使用 MySQL 的 `NOW()`

## 常见问题

### 前台看不到广告位？

1. 检查短代码里的 `slot` 标识是否写对（要和后台的 `slot_key` 一致）
2. 检查广告位是否**已启用**
3. 用管理员账号登录刷新页面，如果短代码写错会输出一行 HTML 注释提示

### 支付成功后广告没上线？

1. 确认 **设置 → 固定链接** 已保存过（支付回调依赖伪静态规则）
2. 到 **支付设置** 页点「易支付接口自检」，确认接口本身是通的
3. 查看 **订单管理**，看订单状态是否变为了 `paid`

### 提示"订单创建失败"？

这是数据库层面的问题。请到 **自助广告 → 仪表盘**，页面会显示**上次数据库错误的原文**
（含时间、错误信息、SQL 语句），也可以到 **支付设置** 页点「数据库修复」自动补齐缺失的表和字段。

> 普通用户只会看到「订单创建失败」这一句，不会泄露数据库细节；管理员能看到完整原因。

### 广告位卖出后消失了？

如果站长把广告手动放到了比较靠后的格子（比如每行 4 格却放到第 7 格），
页面会一直显示到那一格。这是**预期行为**，否则那条广告用户就看不见了。

### 改了广告位容量，前台没变化？

`max_items` 是**每行容量**。渲染列数和下单校验共用同一套规则。
如果改完没生效，检查一下浏览器缓存（`Ctrl + F5`）。

### 支付密钥保存在哪？安全吗？

存在 `wp_options` 表里（`wsa_alipay_config` / `wsa_epay_config`）。
建议配合数据库访问控制和定期备份。**不要**把密钥提交到 Git 仓库。

### 参与贡献

欢迎提交 Issue 和 Pull Request。提交前请：

1. 确认代码能通过 PHP 语法检查（`php -l`）
2. 不要提交任何真实的支付密钥、AppID 等敏感信息
3. 涉及数据库结构变更时，记得同时更新 `WSA_DB_VERSION` 并在 `WSA_DB::migrate()` 里补迁移逻辑

### 安全设计要点

- 金额**只在服务端计算**（`WSA_Ad_Slots::calc_amount()`），前端无法篡改
- 下单走**数据库事务 + 行锁**，加锁顺序固定为「先 `wsa_ad_slots`，再 `wsa_orders`」
- 支付回掉**校验 app_id 与金额**，`mark_paid()` 全程幂等
- 前台输出统一转义，用户输入经 `esc_html` / `esc_url` / `esc_attr` 处理
- 后台操作全部走 nonce 校验
